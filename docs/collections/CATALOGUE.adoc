== Purpose and evidence

Stuff of Awe is building maintained, practical collections for the mathematics,
logic and formal-methods communities. ECHIDNA supplies an initial coverage floor,
not a boundary: resources need not integrate with ECHIDNA or belong to our estate.

This ledger accounts for all *141 declared ProverKind variants* in
https://github.com/hyperpolymath/echidna/blob/a81467bbbf0b142dc016eda7c9b16b55d3962734/crates/echidna-core/src/prover_kind.rs[ECHIDNA at commit a81467b].
There are 100 entries outside the contiguous 41-entry internal dispatcher family.
These are declaration counts, not counts of independent products, tested adapters,
working installations or completed collections. Aliases and related ecosystems
share a collection where appropriate.

* *Existing*: a local repository exists; its completeness and link health still require review.
* *Starter*: an initial curated collection; ongoing expansion and review remain.
* *Family starter*: the named tool has an annotated link in a family list; this is not a separate tool-specific repository or an executed integration.
* *Planned*: a proposed repository name, deliberately not a link to a nonexistent repository.
* *Internal*: an ECHIDNA/estate dispatch category to document within a shared type-systems collection.

`Planned` records a research topic, not a commitment to create one repository
per variant. Prefer a useful family collection or an existing maintained
upstream list when several tools belong together.

The upstream awesome-list survey is preliminary, not exhaustive. A search that
finds no exact name does not establish that no useful collection exists.

== Verification tools and language resources

The ECHIDNA variant list is a declaration inventory. Its
https://github.com/hyperpolymath/echidna/blob/main/.machine_readable/verification-integrations.a2ml[verification integration ledger]
separates backend declarations from corpus-only, internal-proof, and
non-prover roles. A language or specification notation does not need its
own `ProverKind` merely to be useful.

* Rust verification: https://github.com/stuff-of-awe/awesome-provable[awesome-provable]
  groups Creusot with Pearlite, Verus, Kani and Aeneas in one verifier section.
  Pearlite is part of Creusot, not another solver. Do not create five thin
  collection repositories for these related tools.
* Ada/SPARK: ECHIDNA declares a GNATprove backend. The external
  https://github.com/ohenley/awesome-ada[awesome-ada] already covers Ada and
  SPARK; review contributions there before starting a duplicate local list.
* Chapel and ATS2: neither is an ECHIDNA prover. Chapel is used as proof-search
  compute infrastructure; ATS2 is a programming language and type system.
  Language-resource collections remain candidates, subject to independent
  curation and compiler-level verification of any first-party tools included.

call for one, contribution guidance and a dated review. A repository name alone
does not count as maintained coverage. See link:MAINTENANCE.adoc[the maintenance policy].
